Please refer to the following definition for the entire parts of the current document:

\begin{itemize}
    \item \textbf{Controller}: A component that contains all functionalities and routine for producing a specific response to a specific request;
    \item \textbf{Coordinator}: A component (or better a module/sub-module) that supports the manager in its activity;
    \item \textbf{Handler}: A component that contains all functionalities and routines that are executed in response to a specific system event;
    \item \textbf{Manager}: A component that contains all functionalities and routines for actively managing the scenarios. It is the head of the operation.
    \item \textbf{Monitor}: A component that acts as referee for the access on shared resource; 
\end{itemize}

\section{Component Description}

\subsection{Initialization}
\label{subsec:Init}
The initialization component \textbf{shall} take in charge all the aspects to get the SrvcMgr module (in anyone of its part) operative. Furthermore, the component offers service calibration support, permitting externally to calibrate services off.

\subsection{Execution Manager}
\label{subsec:ExecManagerStatic}

\RequirementTag{ADS_SrvcMgr}{002}
\\
The Execution Manager \textbf{SHALL}:

\begin{enumerate}
	\item Read the PermitExecution interface updated by SUM_SUSD
	\item Compute the ExecutionStatus for the other Submodules according to:
	\begin{itemize}
	  \item The data read from item 1)
	  \item A bit-mask that may be either user-defined or equal to 0xFE
	\end{itemize}
	\item Update the ShutdownPermission interface according to:
	\begin{itemize}
	  \item The data read from item 1)
	  \item A bit-mask that may be either user-defined or equal to 0xFE
	  \item The state of requests coming from the SPM
	  \item The state of the learning session request.
	\end{itemize}
\end{enumerate}

\subsection{Learning Session Manager}
\label{subsec:LrngSessionManagerStatic}

The Learning Session Manager is responsible for implementing the DIDs and RIDs related to the Learning Session handling. The Learning Session Manager \textbf{SHALL}:
\begin{itemize}
\item Receive the diagnostic request (DIDs or RIDs) from Dcm through the dedicated port interface.
\item Execute the runnable related to the service requested by Dcm.
\begin{itemize}
\item Call the appropiated SD API for retreiving the information related to the Learning Session according to the RID/DID requested.
\end{itemize}
\item Return to Dcm the Output data requested through the specific service.    
\end{itemize}


\subsection{Service Manager}
\label{subsec:ProjSpecServiceManagerStatic}

The Service Manager is responsible for handling the Service State. The Service Manager \textbf{SHALL}:
\begin{itemize}
\item Implement the C/S operation Runnable_SrvcMgr_ActivateServices().
\item Track if request coming from SPM is ongoing in order to prevent that the Execution Manager votes for shutdown.
\end{itemize}

\subsection{Calibration Controller}
\label{subsec:CalibControllerStatic}
The Calibration Controller is responsible for managing the calibration status of configured services. The Calibration Controller \textbf{SHALL}:
\begin{itemize}
\item Implement the APIs SrvcMgr_DisableService and SrvcMgr_DisableServiceGroup that will be called by a user callout to change the state of services through standard SD APIs.    
\end{itemize}
