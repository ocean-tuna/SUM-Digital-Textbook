API/Data Interaction

The RTA-SUM_SPM provides the following scheduled functions:

  • Spm_SoftMgr_MainFunction

  • Spm_PowrMgr_MainFunction

The RTA-SUM_SPM is the provider of the following SERVICE APIs:

  • To SWC: Spm_ActivateProfile

  • To SWC: Spm_DeactivateProfile

  • To SWC: Spm_GetDTCIdentifier

The RTA-SUM SPM is the consumer of the following SERVICE APIs:

  • From CanIf : CanIf_Transmit

  • From EthSM : EthSM_RequestComMode

The RTA-SUM_SPM exchanges the following DATA by RTE APIs:

  • RTA-SUM_SUSD -> RTA-SUM_SPM: Spm_PermitExecution

  • RTA-SUM_SPM -> RTA-SUM_SUSD: Spm_ShutdownPermission

  • RTA-SUM_SPM -> RTA_SUM_SSFM: Spm_LossOfNodeIndication_lfc

  • RTA-SUM_SPM -> RTA-SUM_SrvcMngr: Spm_ServiceActivationStatusNotification_Ifc

  • RTA-SUM_SPM -> BswM: Spm_BswMGroupSwitchTxReq

  • RTA-SUM_SPM -> BswM: Spm_BswMGroupSwitchRxReq

Module Configuration Overview

The RTA-SUM_SPM is deployed as a configurable software to address multiple project specific needs by the same implementation instance.

The Configuration of the RTA-SUM_SPM module follows the AUTOSAR guidelines for a Complex Device Driver.

RTA-SUM_SPM SHALL appear as single own instance for each ECU: No multiple RTA-SUM_SPM instances are allowed for the same ECU.

The configuration of RTA-SUM_SPM appears as follows:

  • SPM: main root configuration container of the module

    • SpmConfigSet: project specific configuration set

      • SpmLowVoltagePowerInfo: Container for the configuration of LowVoltageSoftwareActivationPriorityRequest service

      • SpmPowPrf: Container to configure the power profile and their attributes

        • SpmProfileSwDep : Container defines the Software Dependencies for the current profile

      • SpmPgttEntries: Container to configure the Power Graph and its attributes

        • SpmTrgDvc: Container defines all the Device can be reached by the current instance of the SPM

          • SpmTrgDvcHndlngInfo : The current container addresses (if configured) how the current SPM shall manage the target device. Not all the target device are directly managed by the current SPM instance. In case the current SPM runs on a INTERMEDIATE node and the Target Device is an EDGE, then whether SPM handles this edge node, this container reports the useful information on how to consume the wake-up frame information for the current device.

        • SpmWkngDvc: Container defines all the IP configurations as Source Node of the current instance of the SPM

          • SpmTrgDvcInfo : Container defines the mapping between the Target device to be reached and the wake-up sequence to use

        • SpmWkUpSeq: Container defines a Wake-up sequence and its related steps

          • SpmWkUpSeqStep : Container defines the parameters to define a wake-up step to be used in a sequence

    • SpmGeneral: general parameters that are common for using the SPM within an ECU

      • SpmCANWkUpFrmRef: Container to reference all the wake-up frame ON CAN bus in scope to the SPM instance

      • SpmETHWkUpFrmRef: Container to reference all the wake-up frame ON ETHERNET bus in scope to the SPM instance

      • SpmVLANCom: Container for the configuration of VLAN communication for configurable interfaces.

        • SpmVLANComPwrMgrHeartbeat: Container for the configuration of VLAN communication for configurable interfaces.

        • SpmVLANComPwrMgrWakeupFrames: Container for the configuration of VLAN communication for configurable interfaces.

        • SpmVLANComPwrMgrWakeupFramesMulticast: Container for the configuration of VLAN communication for configurable interfaces.

        • SpmVLANComSwrMgrInfo: Container for the configuration of VLAN communication for configurable interfaces.

      • SpmGenerateInitRunnable: A parameter that shall generate SPM init runnable if it.. list-table:: Configuration Containers

      • SpmActDeactRetryPeriodicity: Period in milliseconds for retries of activation/deactivation requests.

      • SpmInitFuncPeriodicity: Period in milliseconds that configures the runnable init function periodicity. This parameter is required when SpmGenerateInitRunnable is set to TRUE.

      • SpmWkUpHelperFunction: The parameter defines the name of the wake-up helper function to be used by SPM, in case the ECU support the SDV-8217 defined Custom wake-up mechanism. The support of this function is valid only for intermediate nodes as CHM MCU.

      • SpmPermitExecutionMask: The parameter is a bitmap (1 Byte length) that defines the DON’T CARE wake-up sources that trigger the SPM execution. The DON’T CARE wake-up sources needs to be configured as 1.

      • SpmBurstPhsPeriodicity: BurstPhsPeriodicity is a period less than the usual one, that happens as soon as SPM starts counting and sharing its heartbeat and the wake-up frame. This period is maintained for the first 3 counts. The parameter configures the message periodicity in milliseconds for this phase before switching to the normal one.

      • SpmSMMainFuncPeriodicity: Periodicity in milliseconds for the execution of SPM Software Manager functionalities.

      • SpmWakeupFrame: Wake up frame for the device.

      • SpmWakeupBit: Indicates the related bit for wake up in the frame.

      • SpmHBShutdownDelayMs: Initial value for the calibration parameter indicating the time (in ms) the PM has to wait, after the last burst HeartBeat has been sent, before allowing the shutdown (Keep-Awake Timer).

      • SpmDiagnostic: Container with the reference needed for DIDs.

      • Spm_SmFrame_QueueLength: Maximum queue length of SM Frame Rx messages.

      • Spm_PmETHwakeUpMULTIC_QueueLength: Maximum queue length of PM eth wakeup Multicast Rx messages.

      • Spm_LocalRequests_QueueLength: Maximum queue length of local activation/deactivatino requests as well as diagnostic requests.

      • Spm_PmETHwakeUpUNIC_QueueLength: Maximum queue length of PM eth wakeup Unicast Rx messages.

      • Spm_PmHeartbeat_QueueLength: Maximum queue length of PM eth wakeup Multicast Rx messages.
